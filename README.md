# AIRA Fusion website

The public website for **AIRA Fusion** and its platform **AIRA Nexus**. It is a static site: plain HTML, CSS and JavaScript, generated by one small Python script, with no framework and no runtime dependencies. It contains no product screenshots. Every visual is SVG or canvas drawn in code.

## Build and preview

```bash
python build.py            # writes ./public
python build.py --serve    # builds, then serves http://localhost:8090
```

CSS and JavaScript URLs include content hashes so new builds invalidate cached assets.

Links are relative, so `public/index.html` also opens directly from disk.

## Light and dark mode

The site defaults to dark mode. The theme toggle is temporarily hidden and saved visitor preferences are ignored while switching is disabled. The logo icon is unchanged; each mode uses its supplied navy or white wordmark.

Set the site-wide default in the front matter at the top of `src/pages/index.html`:

```yaml
default_theme: dark
```

Use `light` or `dark`, then run `python build.py`. The default applies to every page, including direct links and without JavaScript. To restore the toggle and saved visitor preferences, set `toggleEnabled` to `true` in `src/static/js/theme.js` and rebuild.

The single AIRA Nexus navigation item combines the platform overview, six product cards, architecture and deployment specifications. These are maintained together in `src/pages/nexus.html`. Product links use `nexus.html#home`, `#studio`, `#gateway`, `#runtime`, `#signal` and `#data`. The former `platform.html` page redirects to Nexus and maps legacy `#hub` links to `#home`.

## Ask AIRA website guide

The floating luminous-orb chat uses local, prepared FAQ answers and keyword matching. It does not call an AI service. Questions stay in memory for the current page; refreshing or navigating clears them. Up to 60 messages are retained. Visitors can optionally include this conversation when sending an enquiry.

Edit `src/static/js/aira-config.js`:

```js
recipient: "info@airafusion.com",
emailSubject: "AIRA website enquiry",
```

The recipient is **your team's receiving mailbox**, currently `info@airafusion.com`. FormSubmit must activate that mailbox before enquiries can be delivered. Leaving the recipient empty disables sending. Do not put mailbox passwords, SMTP credentials or private keys in this public file. This configuration is shared by the Contact Us form and avatar chat. You can edit the greeting and avatar path, or set `enabled: false` to hide only the chat (the contact form still works).

Run `python build.py --serve` to preview. Once the recipient is configured, submit a test enquiry from the widget, open the FormSubmit activation email in that mailbox (check spam), and confirm it. Send another test after activation and verify receipt before publishing. Changing the receiving mailbox requires activation again. FormSubmit also supplies an opaque recipient token that can replace the email in `recipient`. Rebuild and redeploy after every config change. Sending needs an HTTP(S) page and an internet connection; use the preview server instead of opening an HTML file directly.

Enquiries go through [FormSubmit](https://formsubmit.co/documentation), which currently advertises free unlimited submissions and retains submissions for 30 days. The email includes name, reply-to email, company, message, page URL, and the transcript only when the visitor checks the inclusion box. This implementation does not send automatic copies to visitors. The widget includes a honeypot and prevents duplicate clicks during a request; these do not replace server-side abuse protection. Browser-visible recipient settings are public, even with a token. Provider acceptance is not proof of inbox delivery.

The nginx Content Security Policy permits requests to `https://formsubmit.co`; replicate that `connect-src` permission if you deploy behind another host's CSP. No email is sent merely by opening the widget or asking a question. The Contact Us form uses the same delivery code and recipient as the chat, and preserves entered details if delivery fails. Direct email links remain available as a fallback.

## Updating the FAQ answers

The editable FAQ content lives in `src/static/js/aira-faq.js`, separate from email settings and chat code. Each entry has a button `label`, matching `keywords`, a prepared `answer`, and a `page` link to the website source. The chat loads this file locally; there is no AI, crawling or automatic content rewrite at runtime.

Whenever website content changes, ask: **"Update the Ask AIRA FAQs from the current website content."** Review the source pages in `src/pages/`, refresh this FAQ file, add or remove topics as needed, and verify the answer wording and source links. Keep pricing and certification claims limited to what the source pages actually say. Preserve the shared mailbox configuration. Run `python build.py`, `python tools/check_site.py` and `node tools/check_faq.cjs`, then redeploy. Every build versions the FAQ script so visitors get the updated content.

## Deploy

```bash
python build.py
docker build -t aira-website .
docker run -p 8090:8080 aira-website
```

The image uses rootless nginx on port 8080 and serves security headers, including a CSP, plus gzip and a custom 404 page. Put TLS in front of it with your ingress or CDN.

## Search discovery

```bash
python build.py
python tools/check_search.py
python tools/check_site.py
node tools/check_contact.cjs
```

The build generates lowercase `robots.txt` and `sitemap.xml` at the site root. The sitemap contains only indexable, canonical pages; the legacy Platform page points its canonical to Nexus and is excluded. The error page carries `noindex`. Crawlers can read the page content directly from HTML without JavaScript.

The current `User-agent: *` rule allows all crawlers, including search and AI search bots. It also permits training crawlers; training permissions are separate from search visibility. No crawler policy has been restricted.

After deployment, verify that `https://airafusion.com/robots.txt`, `/sitemap.xml` and every listed page return HTTP 200, missing URLs return HTTP 404, and the CDN/firewall allows legitimate crawlers. Confirm that HTTPS and the canonical hostname are enforced at the ingress. Submit the sitemap in Google Search Console and Bing Webmaster Tools and inspect the Home and Nexus URLs. Submission and crawl access do not guarantee indexing or AI citations.

Guidance: [Google sitemaps](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap), [Google AI search features](https://developers.google.com/search/docs/appearance/ai-features), [OpenAI search crawlers](https://developers.openai.com/api/docs/bots), [Bing sitemaps](https://www.bing.com/webmasters/help/sitemaps-3b5cf6ed).

## Layout

```
build.py                 page assembly: header, footer, meta, icons, diagrams, sitemap
src/pages/*.html         page bodies, each with a small front-matter block (title, description, nav)
src/pages/insights/      articles
src/static/css/site.css  the design system (tokens in :root)
src/static/css/glow.css  the glow-glass layer loaded after site.css (glass panels, light ribbons, pedestal, product suite, deploy strip); tokens at the top
src/static/css/light.css the light palette, neutral surfaces and restrained accents; loaded last
src/static/js/site.js    light-ribbon waves, dotted globe, plane diagram, request lifecycle, audit chain, policy stream, tabs, form
src/static/js/globe-data.js  1-degree land mask for the home globe (Natural Earth 1:110m land, public domain); loaded only by index.html
src/static/img/brand/    approved brand artwork (supplied files, resized only)
tools/og-card.html       source of img/og-card.png (1200x630 share image)
```

To change the navigation or footer, edit `NAV` or `FOOTER` in `build.py` once. Every page picks it up.

Placeholders inside pages: `{{root}}`, `{{icon:NAME}}`, `{{hex:PRODUCT}}`, `{{plane}}`, `{{doors}}`, `{{hexfield}}`, `{{cta}}`, `{{email}}`. The build fails if any `{{…}}` is left unresolved.

## Brand

- **Logo**: only the approved AIRA Fusion artwork is used, never redrawn. `aira-icon-master.png` is the master icon as supplied. `aira-icon-{512,192,64,32}.png`, `favicon.png` and `apple-touch-icon.png` are the same file, cropped and resized. `aira-wordmark-{white,navy}.png` is the approved AIRA FUSION wordmark from the brand pack. When vector files arrive, drop them in with the same names.
- **Colours**: Midnight Navy `#07192B`, Deep Navy `#0A1F3D`, AIRA Blue `#006CFF`, Electric Cyan `#00CFFF`, Ice Blue `#D9F4FF`.
- **Website palette**: pale blue-gray backgrounds and white card surfaces, charcoal text and restrained teal-blue accents. The original logo icon (including its dark interior) is unchanged; light surfaces use the supplied navy wordmark.
- **Type**: Michroma (wide display) for names and section titles, Montserrat for headings and micro-labels, Inter for text, JetBrains Mono for code-style labels. All from Google Fonts.
- **QR code**: `img/qr-airafusion.svg` encodes https://airafusion.com. Regenerate it with the `qrcode` Python package if the URL changes.

## Content rules

- Claims follow the AIRA Sales Kit (`../AIRA-Sales-Kit`), which was checked against the AiraNexusV5 codebase on 2026-09-25. When a product fact changes, update both.
- Say **"AI Solution"**, never "EIM". **"AI App"** is a reserved name and must not appear.
- Keep the assurance table honest. There is no SOC 2, ISO 27001 or pen test yet. Never claim one early.
- Do not publish customer names, adoption figures or ROI numbers until they are measured and approved.
- The contact form opens a pre-filled email to `info@airafusion.com` and stores nothing. Change `CONTACT_EMAIL` in `build.py` to point it somewhere else.

The security model in one paragraph

AIRA Nexus is deployed inside your perimeter on Kubernetes. All access to approved models, agents and AI Solutions goes through one door: AIRA Gateway. Nexus and external applications share this controlled, audited entry point, while AIRA Runtime manages execution and environments. The baseline network policy denies all other egress unless an operator explicitly declares it. Every person and service authenticates as a Nexus identity, and every request is authorized server-side by one decision function. Policies, guardrails and budgets are enforced before a model is called. Consequential events are written to an audit log that the database itself protects from alteration.

Controls

Defence in depth, layer by layer.

Deployment & residency

Your data never leaves your infrastructure

  • PostgreSQL, Redis, Qdrant, MinIO and Temporal are self-hosted in the cluster
  • AIRA Fusion does not operate, monitor or access deployments unless you grant support access
  • Cloud models are off unless enabled, customer-keyed, and reached only through Gateway guardrails and DLP
  • Air-gapped operation with local models and offline licence verification
Identity & access

One identity, one decision function

  • Keycloak SSO over OIDC and SAML, integrated with your identity provider; native TOTP MFA
  • JWTs with a revocation denylist, refresh-token rotation and an RS256 option
  • The production profile refuses to start with development escape hatches enabled
  • Keys are credentials bound to an identity: shown once, rotatable, never retrievable
Isolation & network

Separation enforced below the application

  • Row-level security enrolled and forced on tenant tables, tenant context set per transaction
  • Retrieval only searches collections the requesting identity may read
  • Enterprise database connections are admin-managed, read-only by default, every query audited
  • Non-root containers; the Kubernetes security baseline is checked in CI
Encryption & secrets

Envelope encryption with rotation

  • Stored secrets and sensitive fields encrypted with a local KMS, HashiCorp Vault or AWS KMS
  • Keys rotate; previous keys stay decrypt-only
  • Deployments generate their own secrets at first install; nothing is baked into images
  • An encrypted connections vault for reusable credentials; secret scanning in CI

Governance that lives at the call, not in a policy PDF.

AI Endpoints

Models, fallbacks, routing, guardrails, data policy, a security level, limits and access grants in one governed contract. Transition mode records every raw-model call.

{{icon:layers}}

Policy hierarchy

Organisation → department → workspace → app → user → model. A narrower scope may tighten a rule but never loosen it.

{{icon:filter}}

Guardrails & DLP

Packs for prompt injection, PII and blocked topics. DLP runs before and after the completion, and PII can be redacted at trigger ingress.

{{icon:search}}

Grounding

Knowledge answers cite the source passage. A grounding gate abstains when the support is too weak to answer.

{{icon:coins}}

Runaway control

Per-key budgets and rate limits, a per-run cost cap on actual spend, and agent trees under hard cost, time, call and depth budgets.

{{icon:approve}}

Human oversight

Approval gates on any AI Solution or workflow step, showing exact inputs and the proposed action. Decisions are recorded.

Audit & evidence

A record that cannot be quietly rewritten.

Each entry is hash-chained to its predecessor, and a database-level WORM trigger blocks updates and deletes. Maintenance such as retention runs only through an explicit, audited path that re-anchors the chain.

  • AI runs, approvals, policy decisions and administrative actions, each timestamped and attributed
  • Verification on demand; CSV or JSON streaming export to your SIEM, GRC or archive
  • Per-node run records that re-render exactly as they first appeared
